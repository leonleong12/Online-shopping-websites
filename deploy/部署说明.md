# Windows 伺服器部署

本指南適用於更新既有 NovaMart 伺服器，不會搬入本機資料庫或覆蓋伺服器圖片。需要 Java 25、SQL Server 和 `sqlcmd`。請勿把密碼、SMTP 授權碼或 AI API Key 寫進程式碼、SQL、部署 ZIP 或 GitHub。

## 本機建置

```powershell
cd frontend-orange
npm ci
npm test
npm run build
cd ..
mvn test
mvn package
```

JAR 產生於 `target\online-shop-0.0.1-SNAPSHOT.jar`。前端靜態檔已由 Vite 放入 JAR。

## 伺服器更新

1. 在運行網站的 PowerShell 按 `Ctrl+C`，停止舊版本。
2. 備份伺服器現有 JAR 和 `uploads` 資料夾。更新時保留伺服器自己的圖片，不要用本機 `uploads` 覆蓋。
3. 將新 JAR、`deploy` 資料夾及根目錄的 `migration_*.sql` 上傳到網站目錄。不要執行 `schema_sqlserver.sql`；它是新資料庫的結構參考，不是既有資料庫升級入口。
4. 在具備 SQL 管理權限的伺服器 PowerShell 執行：

```powershell
cd "C:\Users\Administrator\Desktop\Website"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\deploy\Update-Database.ps1' -DbHost 'localhost\SQLEXPRESS'
```

升級工具會先建立並驗證 SQL 備份，再執行增量遷移。只有看到 `NOVAMART_DATABASE_UPDATE_OK` 且沒有錯誤，才啟動新 JAR。不要用低權限的 `online_shop_app` 帳號執行結構遷移。

## 啟動

建議沿用已成功啟動網站的 PowerShell 視窗，這樣原有 `DB_*` 環境變數仍在。若必須開新視窗，重新設定資料庫連線變數；密碼請在終端機隱藏輸入，不要依賴另外彈出的憑證視窗：

```powershell
$env:DB_HOST = 'localhost\SQLEXPRESS'
$env:DB_USER = 'online_shop_app'
$secure = Read-Host '輸入資料庫密碼（輸入時不會顯示）' -AsSecureString
$ptr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secure)
$env:DB_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($ptr)
[Runtime.InteropServices.Marshal]::ZeroFreeBSTR($ptr)
$secure.Dispose()
```

郵件設定為選用；不設定時網站仍可啟動，但找回密碼和發貨通知無法寄送。使用你自己的寄件郵箱及重新產生的 SMTP 授權碼，不要把授權碼存入 Git：

```powershell
$mailbox = Read-Host '輸入寄件郵箱'
$env:MAIL_HOST = 'smtp.qq.com'
$env:MAIL_PORT = '587'
$env:MAIL_USERNAME = $mailbox
$env:MAIL_FROM = $mailbox
$env:MAIL_FROM_NAME = 'NovaMart 客服'
$env:MAIL_AUTH = 'true'
$env:MAIL_STARTTLS = 'true'
$env:MAIL_SSL = 'false'
$secureMail = Read-Host '輸入 SMTP 授權碼（輸入時不會顯示）' -AsSecureString
$ptr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secureMail)
$env:MAIL_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($ptr)
[Runtime.InteropServices.Marshal]::ZeroFreeBSTR($ptr)
$secureMail.Dispose()
$env:SHOP_PUBLIC_URL = 'https://你的實際網站網址'
```

接著啟動並保留這個 PowerShell 視窗：

```powershell
java -jar '.\online-shop-0.0.1-SNAPSHOT.jar'
```

看到 `Tomcat started on port 8081` 和 `Started OnlineShopApplication` 後，再從瀏覽器檢查網站。`SHOP_PUBLIC_URL` 應使用顧客實際訪問的 HTTPS 網址，否則郵件連結會錯誤。

## 注意

- 資料庫遷移只在版本要求時執行；不要重建或刪除既有 `online_shop` 資料庫。
- `uploads`、資料庫內容和執行環境變數不包含在 GitHub 原始碼中，需分別備份。
- 一次性清庫檔案不納入 GitHub。執行清庫前必須先確認範圍並驗證備份。
