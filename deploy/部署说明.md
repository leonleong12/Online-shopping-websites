# NovaMart 伺服器更新（2026-10-21）

這個包包含已整合前端的 JAR，以及分類管理、訂單、精選、錢包、卡密、客服和 AI 協議的增量 SQL。沿用伺服器原有資料，不搬入本機資料庫。

本次包含分類管理、QQ 郵箱找回密碼及發貨通知郵件，郵件顯示名稱為「NovaMart 客服」。需先執行 SQL 更新再替換及啟動新 JAR。更新腳本會先備份並驗證資料庫，所有遷移可重複執行；不會搬移或覆蓋伺服器原有商品、圖片、帳戶、訂單及錢包資料。

不需要在伺服器安裝 Node.js、Maven 或 SSMS。沿用已能啟動網站的 Java 25、SQL Server、sqlcmd 和原有資料庫帳號。這不是全新安裝包，要求既有 online_shop 資料庫及 online_shop_app 資料庫用戶。

## 1. 停止網站並備份舊檔案

在伺服器正在運行網站的 PowerShell 按 Ctrl+C。若網站由 Windows 服務或排程啟動，先停止相應服務或排程。

在伺服器 PowerShell 執行：

```powershell
cd "C:\Users\Administrator\Desktop\Website"
$releaseBackup = Join-Path (Get-Location) ("backup-before-" + (Get-Date -Format "yyyyMMdd-HHmmss"))
New-Item -ItemType Directory -Path $releaseBackup | Out-Null
Copy-Item -LiteralPath '.\online-shop-0.0.1-SNAPSHOT.jar' -Destination $releaseBackup
if (Test-Path -LiteralPath '.\uploads') {
    Copy-Item -LiteralPath '.\uploads' -Destination $releaseBackup -Recurse
}
Write-Host "舊程式與圖片備份：$releaseBackup"
```

保留 Website 裡的 uploads、原有環境變數與外部設定檔。不要用本機的 uploads 覆蓋伺服器圖片。

## 2. 上傳並解壓整個更新包

把 ZIP 上傳到伺服器，解壓後將其中所有檔案放進：

`C:\Users\Administrator\Desktop\Website`

覆蓋同名 JAR。確認 `online-shop-0.0.1-SNAPSHOT.jar` 在 Website 根目錄；`Update-Database.ps1` 和 `upgrade.sql` 在 `Website\deploy`；`migration_*.sql` 在 Website 根目錄。不要執行舊的 `schema_sqlserver.sql`，它不是這次的升級入口。

## 3. 備份並更新 SQL

在伺服器 PowerShell 執行：

```powershell
cd "C:\Users\Administrator\Desktop\Website"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\deploy\Update-Database.ps1' -DbHost 'localhost\SQLEXPRESS'
```

腳本使用 Windows 身分連接 SQL，無需 SSMS 或輸入資料庫密碼，但目前的 Windows 帳號必須具有 SQL 備份與結構更新權限。先建立 COPY_ONLY 資料庫備份並執行 VERIFYONLY，再更新 SQL；畫面會顯示 `.bak` 檔案位置，請保留並另行備份。

只有出現 `NOVAMART_DATABASE_UPDATE_OK` 且沒有紅色錯誤，才進行下一步。若顯示登入失敗、找不到資料庫或權限不足，先停在這一步；不要改用低權限的 online_shop_app 強行升級，也不要重建資料庫。

增量 SQL 可重複執行，缺少的結構才補建；保留帳號、商品、錢包餘額、流水、儲值碼、卡密與 AI 設定。舊的已付款 PAID 訂單會統一轉成 PROCESSING（處理中）。全部 SQL 在同一個外層事務中執行，任一步錯誤便停止，未提交變更由連線關閉時回滾。

## 4. 用原本的資料庫帳號啟動

沿用原本已能成功啟動的 PowerShell 視窗與 DB_* 環境變數，並在同一個視窗設置 QQ 郵件參數後執行：

```powershell
$env:MAIL_HOST = 'smtp.qq.com'
$env:MAIL_PORT = '587'
$env:MAIL_USERNAME = '2104878272@qq.com'
$env:MAIL_PASSWORD = '<新的 QQ SMTP 授權碼>'
$env:MAIL_FROM = '2104878272@qq.com'
$env:MAIL_FROM_NAME = 'NovaMart 客服'
$env:MAIL_AUTH = 'true'
$env:MAIL_STARTTLS = 'true'
$env:MAIL_SSL = 'false'
$env:SHOP_PUBLIC_URL = 'https://你的公网域名或IP'
java -jar '.\online-shop-0.0.1-SNAPSHOT.jar'
```

`MAIL_PASSWORD` 只填 QQ 郵箱後台生成的 SMTP 授權碼，不是 QQ 登錄密碼，也不要把授權碼寫入 JAR、SQL、前端或 ZIP。你之前貼出的授權碼已經暴露，請先在 QQ 郵箱後台撤銷並重新生成一個新的，再填入上面的 `<新的 QQ SMTP 授權碼>`。`SHOP_PUBLIC_URL` 必須填用戶實際訪問網站的 HTTPS 地址，否則找回密碼郵件中的連結會指向錯誤位置。

若是新開的 PowerShell，需要先設置原有參數。以下用隱藏輸入讀取目前的資料庫密碼，不要把範例文字當成密碼：

```powershell
cd "C:\Users\Administrator\Desktop\Website"
$env:DB_HOST = 'localhost\SQLEXPRESS'
$env:DB_USER = 'online_shop_app'
$dbCredential = Get-Credential -UserName 'online_shop_app' -Message '輸入目前的資料庫密碼'
$env:DB_PASSWORD = $dbCredential.GetNetworkCredential().Password
$env:MAIL_HOST = 'smtp.qq.com'
$env:MAIL_PORT = '587'
$env:MAIL_USERNAME = '2104878272@qq.com'
$env:MAIL_PASSWORD = '<新的 QQ SMTP 授權碼>'
$env:MAIL_FROM = '2104878272@qq.com'
$env:MAIL_FROM_NAME = 'NovaMart 客服'
$env:MAIL_AUTH = 'true'
$env:MAIL_STARTTLS = 'true'
$env:MAIL_SSL = 'false'
$env:SHOP_PUBLIC_URL = 'https://你的公网域名或IP'
java -jar '.\online-shop-0.0.1-SNAPSHOT.jar'
```

看到 `Tomcat started on port 8081` 和 `Started OnlineShopApplication` 後，保留該視窗；關閉它會停止網站。前端已放進 JAR，只需這一個網站進程。

## 5. 檢查更新

在伺服器瀏覽器打開 http://localhost:8081，確認能登入、載入商品及訂單。再從自己電腦訪問原本的公網網址，按 Ctrl+F5，以管理員登入後進入「商品管理 → 管理分类」。

確認可以新增、改名、用 ↑ ↓ 排序及隱藏分類；新增或編輯商品時可在下拉框選擇分類。前台只顯示已啟用且有上架商品的分類，沒有商品或只有下架商品的分類不會顯示。隱藏只收起分類入口，不會下架商品，商品仍可在「所有商品」找到。原有 General 名稱及商品歸屬會保留，可由店長自行改名。

若伺服器先前沒有設過 AI，需在客服後台自行填入 API 地址、密鑰、模型和協議；本包不包含本機資料庫或密鑰。

驗證郵件功能：在登入頁點「忘記密碼」，輸入已註冊的郵箱並檢查收件匣及垃圾郵件；使用郵件中的連結設定新密碼。管理員在訂單管理完成發貨後，系統會向訂單帳戶郵箱發送發貨確認，內容包含訂單號、商品清單、支付金額及快遞單號或虛擬卡密。若未設置 `MAIL_PASSWORD`，網站仍可啟動，但不會成功寄信，後端只記錄郵件發送失敗，不影響已完成的業務操作。

從 IntelliJ 啟動時，請把上述環境變數加入 Run/Debug Configuration 的 Environment variables，重新載入 Maven 專案，再停止並重新執行 OnlineShopApplication；本機打開 http://localhost:8081 並按 Ctrl+F5。

## 回退

若程式異常，停止新程式，從 backup-before-* 資料夾複製回舊 JAR，以原啟動方式運行。結構更新以補加欄位與資料表為主；不要自行刪除新表。若需恢復 `.bak`，應在停止網站後由資料庫管理員確認還原時間點，因為還原會丟失備份之後的新訂單與資金變動。
